# 运维指南

## 部署模型

当前版本适合单主机、单进程部署。不要同时运行多个写入同一 `data/app.json` 的实例，也不要把同一状态文件放在无锁共享存储上。

推荐拓扑：

```text
可信客户端 -> HTTPS 反向代理 -> 单个 deepseek2api 进程 -> DeepSeek Web
```

反向代理负责 TLS、可信 Origin、访问控制、请求速率、请求体上限和审计日志。应用进程应使用低权限专用账户运行，并只授予项目目录所需权限。

## 启动与停止

前台启动：

```bash
npm start
```

生产环境可使用系统服务管理器或进程管理器托管 `node src/server.js`。停止时应先停止接收请求，再终止进程，避免状态写入被中断。

## 健康检查

无需认证的轻量检查：

```bash
curl --fail http://127.0.0.1:3000/api/me
```

正常时返回 HTTP 200 和 `authenticated` 字段。`GET /api/protocol` 可用于检查加载的上游版本与路径清单，但两者都不代表 DeepSeek 上游账号一定可用。

端到端检查应使用专用低权限本地 API Key 调用 `/v1/models`，并根据需要定期执行一次最小聊天请求。不要把检查 Key 写进公开配置或命令历史。

## 持久化与备份

唯一运行时状态文件是 `data/app.json`。备份步骤：

1. 停止应用或确保当前没有写入。
2. 复制 `data/app.json` 到加密、访问受控的位置。
3. 记录应用提交版本和 `.env` 中非秘密配置。
4. 验证备份权限与恢复流程。

备份包含可用凭据，保留周期应尽可能短。不要把备份放入仓库、构建产物或普通对象存储桶。

恢复时先停止应用，把备份恢复为 `data/app.json`，确认运行账户可读写，然后启动。读取旧格式时应用会执行兼容规范化，因此首次恢复前应保留只读原始副本。

## 升级

1. 阅读目标提交的配置、存储和接口变化。
2. 停止服务并加密备份 `data/app.json`。
3. 更新代码，确认 `.env.example` 中是否新增变量。
4. 运行 `npm test`。
5. 启动并检查 `/api/me`、`/api/protocol`、账号状态与一个最小 API 请求。
6. 确认稳定后按保留策略处理升级前备份。

不要在多个进程仍运行时替换状态文件。

## 日志与可观测性

- Node.js 启动和未捕获的进程输出由宿主进程管理器收集。
- 业务请求日志只保存在内存，最多 500 条，重启即清空。
- 日志错误字段会脱敏，但路径、owner ID、account ID、模型、状态和耗时仍可能属于内部元数据。
- 不要默认开启 HTTP body、Authorization、Cookie 或完整上游响应日志。

## 常见故障

### 无法登录管理台

- 检查 `APP_ADMIN_USERNAME` 与 `APP_ADMIN_PASSWORD` 是否同时设置。
- 本地用户可能已被管理员禁用；禁用会删除现有用户会话。
- Cookie 有效期为 7 天，过期后需要重新登录。

### OpenAI 接口返回 401

- 确认使用的是创建时返回的本地 API Key，而不是 DeepSeek token。
- Key 明文不会再次显示；丢失后应删除旧 Key 并新建。

### 返回 Account not found

- 确认 Key 绑定账号仍存在且可用。
- 账号触发验证码时不会被视为可用账号。
- 共享账号模式下，创建 Key 的用户仍必须先绑定自己的可用账号。

### 上游限流或验证

- 查看管理台请求日志和账号验证码状态。
- 429 / 503 / `Retry-After` 会被协议层分类并计算退避时间。
- 自动验证码处理默认关闭；优先人工确认挑战内容和账号授权。

### 数据文件损坏

- 停止服务并保留损坏文件副本。
- 验证 JSON 是否完整，避免在运行中直接编辑。
- 从受控备份恢复；没有备份时只能删除文件并重新初始化状态。
