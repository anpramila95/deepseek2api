# 安全与隐私

## 安全边界

本项目面向本地或受控网络中的单实例部署。默认实现提供基础隔离和脱敏，但不是可以直接暴露到公网的完整安全网关。

生产使用至少应满足：

- 仅允许可信来源访问管理台和 `/proxy/*`。
- 通过反向代理提供 HTTPS、访问控制和请求速率限制。
- 使用高强度管理员密码，并限制 `.env` 与 `data/` 的文件权限。
- 不在日志、Issue、聊天记录或截图中分享 `data/app.json`。
- 只绑定已获授权的账号，不把共享账号模式用于绕过上游限制。

## 敏感数据清单

`data/app.json` 可能包含：

- DeepSeek token、用户 ID、设备 ID、DID 和客户端指纹档案。
- 本地会话 ID、用户密码盐与哈希、API Key 哈希和 Key 预览。
- 邀请码、账号状态、验证码状态和请求使用统计。
- 管理台配置的 YesCaptcha Key。
- 当 `PERSIST_ACCOUNT_CREDENTIALS=true` 时，DeepSeek 登录名明文和密码。

因此，即使默认不保存上游密码，也必须把整个文件视为凭据数据库。

## 当前保护措施

- `.env`、运行数据库、日志、浏览器快照、测试输出和常见数据库文件均被 `.gitignore` 排除。
- 本地 API Key 默认由加密安全随机数生成，磁盘只保存 SHA-256 哈希；明文只在创建响应中返回一次。
- 本地用户密码使用独立随机盐后哈希保存。
- 默认不持久化 DeepSeek 登录名明文与密码；旧状态读取时会按当前策略移除旧版明文。
- API 返回账号标识时进行脱敏，不返回 token、设备档案或 Key 哈希。
- 错误响应和内存请求日志会脱敏 Bearer token、常见密钥字段、邮箱和手机号，并限制错误预览长度。
- 会话 Cookie 使用 `HttpOnly`、`SameSite=Lax` 和有效期；退出会删除服务端会话。
- 代理只允许配置白名单中的上游路径，并限制账号访问范围。

## 已知限制

- 服务端默认没有 TLS；会话 Cookie 也未设置 `Secure`。HTTPS 应由受信任的反向代理终止，并应评估补充 `Secure` Cookie。
- 服务默认设置宽松 CORS 响应头。公开部署前应改为明确的可信 Origin。
- 本地用户密码当前使用 salted SHA-256，而不是专用慢速密码 KDF；管理台登录也没有独立的暴力破解防护。
- JSON 状态文件没有静态加密、文件锁或多实例一致性保证。
- 上游 token、会话 ID 和管理台保存的验证码服务 Key 需要以可用形式存在于本地状态中。
- 请求体上限约 110 MiB。反向代理应设置相同或更严格的限制。
- 前端会访问 Google Fonts 与 jsDelivr；高隐私或离线环境应改为自托管资源。

## 凭据持久化策略

保持默认配置：

```env
PERSIST_ACCOUNT_CREDENTIALS=false
```

此模式只持久化脱敏登录标识和上游 token。token 失效后需要重新绑定账号。

只有明确接受风险并需要自动重新登录时才设置：

```env
PERSIST_ACCOUNT_CREDENTIALS=true
```

切换回 `false` 后，下一次读取状态会清空已保存密码并把登录标识替换为脱敏值。执行切换前仍应先保护或安全销毁旧备份。

## 数据清理

彻底重置本地状态：

1. 停止服务，避免文件在删除后立即重建。
2. 删除 `data/app.json`。
3. 清理反向代理日志、进程日志、浏览器下载、截图和外部备份。
4. 如怀疑 Key 或 token 已泄露，在对应系统中主动撤销，而不只是删除本地文件。

删除 `data/app.json` 会同时删除本地用户、会话、绑定账号、API Key、邀请码和设置。仓库不会保存可恢复副本。

## 提交前检查

建议至少执行：

```bash
git status --short --ignored
git grep -n -I -E "(BEGIN (RSA|OPENSSH|EC) PRIVATE KEY|Bearer [A-Za-z0-9._~+/=-]{12,}|sk-[A-Za-z0-9_-]{12,})"
```

同时人工确认没有提交 `.env`、`data/app.json`、HAR、日志、截图、浏览器快照、真实邮箱/手机号或访问 token。发现已经进入 Git 历史的凭据时，应先撤销凭据，再单独评估历史重写；仅删除当前文件不足以消除历史泄露。
